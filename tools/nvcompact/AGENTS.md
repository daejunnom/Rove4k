# NVCompact 작업 규약

이 문서는 Rove4k 내부 개발 도구 `tools/nvcompact/`에 적용한다. 현재 사용자 요청과
루트 [공통 규약](../../AGENTS.md)을 우선한다. 엔진의 제출 파일과 개발 도구의
실행 파일은 서로 다른 산출물이다. NVCompact 자체를 4096바이트로 제한하거나
엔진의 매 노드 비용을 이유로 필요한 파서·오류 처리·도구 의존성을 생략하지 않는다.

## 목표와 구현 자유

- 제출 부문, 실제 입력, 의미·배포 계약과 측정 기준을 먼저 확정한다. 최종 제출물의
  전체 크기, 시작과 정리, 실제 UCI 동작을 따로 확인한다. 개발 도구의 속도와 메모리도
  관리하되 이를 엔진의 기력 개선이나 제출 적격성으로 보고하지 않는다.
- 현재 운영 구현은 Rust다. Node는 npm 진입점과 패키징 경계, 보존한 Python은 과거
  결과 비교용 참조다. Rust 명령이 보존 Python 구현을 숨은 backend로 호출하지 않는다.
  사용자가 선언한 컴파일러·인터프리터·독립 검증기는 명시한 실행 계약으로 호출할 수 있다.
- 알고리즘, 모듈 수, 크레이트 수, 직렬·병렬 구조와 구체 후보 포트폴리오는 개선할 수 있다.
  기존 설계나 특정 도구 버전의 미지원만을 이유로 유효한 개선을 거절하지 않는다.
- 함수와 파일은 책임·변경 이유·소유권에 따라 구성한다. 줄 수, assertion 개수와
  추상화 계층 수를 합격 조건으로 두지 않는다. 공통 계약을 바꾸면 영향 소비자를 함께 갱신한다.

## 압축과 검증

- 의미 보존, 탐색·모델 변경, 배포 변경을 구분한다. 타입, 값, 평가 횟수와 순서,
  부작용, 수명과 관측 계약을 지킨다. 짧은 source가 작은 제출물을 보장한다고 가정하지 않는다.
- 원본 전체 파일과 원래 압축 스트림을 후보로 보존한다. 부문별 허용 후보만 비교하고
  header·loader·payload·산입 대상 옵션을 모두 센다. 원본 선택은 동일 크기 보존이며
  새 압축 기법의 추가 이득이 아니다. 전체 최적성은 조사한 범위 이상으로 주장하지 않는다.
- 기존 버전과의 회귀는 같은 입력·대상·도구·후보 조건으로 관측한다. Rust 이식이라는
  이유로 허용 크기를 늘리거나 과거 기대값을 실제 출력에 맞추어 자동 갱신하지 않는다.
- 복원 바이트 일치, 컴파일 결과 일치, 프로토콜 검사, 규칙 검토와 실제 서버 인수를
  구분한다. 원본 실패를 새 후보의 성공으로 덮거나 실행하지 않은 후보를 채택하지 않는다.
- 실패는 잘못된 원인 로직 또는 전제를 수정한다. 입력 이름별 예외, 숨은 검사 우회,
  자원 설정의 조용한 축소와 실패·미실행의 성공 처리로 해결하지 않는다. 적용 전제가
  성립하지 않는 변환은 그 이유를 밝히고 미적용할 수 있다.

## 실패·미채택 후보의 보존과 재비교

- 의미 있는 압축 시도는 채택 여부와 관계없이 다시 판단할 근거를 남긴다. 원래 입력과
  후보의 식별자, 재생 가능한 편집·생성 경로, 적용 전제, 실제 도구·인자·codec 문맥,
  전체 파일 비용과 검사 결과·거절 이유를 필요한 범위에서 보존한다. hash만 남겨
  변환을 재구성할 수 없게 하거나, 작은 winner만 남겨 실패 원인을 잃지 않는다.
- 같은 크기·더 큰 크기 때문에 미채택한 후보와, 타입·binding·의미·컴파일·진단·복원
  검사에 실패한 후보를 구분한다. 시간·출력·메모리 한도, 환경 부족과 취소로 끝난
  시도는 미완료다. 크기만 측정한 후보를 의미 검증 통과로 표시하지 않는다.
- 도구는 보존한 후보·측정 기록을 유한한 예산 안에서 자동 비교할 수 있어야 한다.
  같은 문맥의 비교와 새 문맥에서의 재측정을 구분하고, 조합 효과는 실제 전체 파일로
  다시 측정한다. 소스나 codec 문맥이 바뀌면 이전에 크기상 불리했던 후보도 다시
  유용할 수 있으므로 이름별 영구 제외나 raw 길이만의 제거 기준을 만들지 않는다.
- 과거에 실패한 후보의 재시도는 원래 실패 기록을 유지한 새 결과로 남긴다. 입력·
  toolchain·계약이 달라지면 기존 offset·크기·검증 상태를 그대로 옮기지 않는다.
  같은 입력에 대한 편집 재생도 현재 적용 조건과 필요한 의미·native·복원 검사를
  다시 통과해야 채택한다. 원인이 해결되지 않은 의미·재현 실패를 크기 이득으로
  무시하거나, 검사를 약화한 재시도를 같은 성공으로 취급하지 않는다.
- 상세 기록과 재구성에 필요한 소스·payload는 소유한 외부 산출물 경로에 보존한다.
  입력별 전체 복사본을 무한히 쌓는 대신 중복 식별과 유한한 저장·탐색 예산을 사용할
  수 있다. 한도 때문에 보존·측정·검증하지 못한 범위를 기록하고, 원본 실패 근거와
  현재 수용 결과의 재현에 필요한 자료를 일반 캐시 정리로 지우지 않는다. Git에는
  검토한 규칙·자체 예제·출처·해시·결과만 공유한다.

## 소유권과 수명

- 작업 시작·재개 시 실제 branch·기준 SHA·변경·원격 상태와 소유 경로를 확인한다.
  다른 작업의 변경, 실행, 브랜치와 자료를 보존한다. 이미 요청된 가역적 구현과 검사는
  자율적으로 진행하며 과거 다른 프로젝트의 역할 배정·일시중지·예산은 상속하지 않는다.
- 빌드·외부 예제 소스·엔진 파일·원시 캠페인 출력은 저장소 밖의 소유 경로에 둔다.
  저장소에는 자체 소스·작은 자체 검증 예제와 검토한 출처·해시·명령·결과를 둔다.
  **외부 비교 엔진의 소스, 압축된 소스, 실행 파일과 아카이브를 벤더링하지 않는다.**
- 읽기 쉬운 정본에서 생성하고 생성물만 직접 수정하지 않는다. 과거 실패 근거와
  재현에 필요한 입력 식별자를 일반 캐시처럼 회수하지 않는다. 삭제 전 최종 경로,
  symlink 경계·소유권·비활성과 보존 여부를 확인한다.
- 실행에는 유한한 시간·출력·CPU·메모리와 취소 범위를 둔다. job 수와 내부 compiler·codec·
  engine worker의 합계를 고려한다. 논리 취소, 프로세스 종료, 결과 수락과 파일·버퍼 회수는
  별개다. Rust `Child`의 단순 drop에 종료를 맡기지 않는다.
- 대용량 검사는 계획과 실제 시작을 분리한다. 계획은 입력·도구를 읽고 현재 자원을
  관측하며 엔진·할당 probe를 실행하지 않는다. 실제 실행은 명시적 시작과 당시 입력·
  자원 재확인을 거친다. 과거의 충분한 자원 관측은 현재 예약이나 할당 보장이 아니다.

## 협업과 완료

- branch·PR·WIP·원격 보호·worktree·배포의 공통 절차는 루트
  [CONTRIBUTING](../../CONTRIBUTING.md)과 [저장소 수명주기](../../docs/REPOSITORY-LIFECYCLE.md)를
  그대로 따른다. 일반 변경은 최신 develop의 feature 브랜치에서 develop 대상 PR로 공유한다.
  도구에 별도 코드 규약이 있다는 이유로 직접 main push나 별도 저장소 흐름을 만들지 않는다.
- 원격 반영이 요청된 작업에서는 의미 있는 진행 단위를 공유한다. WIP와 통합 인수를
  구분하며 공유 이력을 강제로 덮어쓰지 않는다. 일상적인 선택마다 승인 절차를 추가하지 않는다.
- 에이전트가 위험과 주장에 필요한 실제 검증을 수행한다. 기존 유효한 검사를 활용하며
  문구·버그마다 새 프레임워크·fixture·영구 로그를 자동 추가하지 않는다.
- 재사용한 성공은 영향 입력·환경·범위의 일치 근거와 함께 보고한다. 실제 실행,
  재사용, 실패, 자원 차단, 미확보와 미실행을 구분한다. npm 포장, npm 게시, CI 요청과
  관측한 CI 성공도 서로 다른 상태로 보고한다.
