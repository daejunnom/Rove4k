# 저장소·패키지 이름 제안

## 추천 조합

체스 엔진의 1순위 이름은 **Rook4k**, 범용 압축 도구의 이름은 **NVCompact**를 추천한다. GitHub 저장소 경로에는 `rook4k`와 `nvcompact`, npm 패키지에는 `nvcompact`를 사용하는 조합이다. 이름 후보는 이번 설계의 제안이며, 사용자가 확정하거나 원격 저장소를 생성한 상태를 뜻하지 않는다.

`Rook4k`는 체스 기물인 rook와 목표 부문을 바로 연결하고, 요구한 `R` 시작·`4k` 끝을 만족한다. 발음은 “룩 포 케이”로 읽을 수 있다. ASCII 6글자이며, 특정 탐색·평가·언어·병렬화 방식을 이름에 고정하지 않는다.

## 엔진 후보 비교

| 이름 | ASCII 글자 수 | 뜻과 장점 | 선택할 때 고려할 점 |
|---|---:|---|---|
| **Rook4k** | **6** | rook + 4k. 체스 프로젝트라는 뜻이 가장 직접적이다. | 기존 RoveZero/Rovent 계보는 설명에서 연결하면 된다. |
| **Rove4k** | **6** | RoveZero/Rovent 계보를 짧게 이어 간다. | 이름만 봤을 때 체스라는 뜻은 약해진다. |
| **Ray4k** | **5** | 룩·비숍의 이동선과 연결할 수 있고 짧다. | ray의 일반적인 뜻이 넓어 설명이 필요하다. |
| **Rank4k** | **6** | 체스판의 rank를 떠올릴 수 있다. | 순위라는 뜻도 있어 검색 문맥이 넓다. |
| **R4k** | **3** | 조건을 만족하는 가장 짧은 실용 후보다. | 이름 자체가 전달하는 정보가 적다. |

직관성이 가장 중요하면 **Rook4k**, 사용자 프로젝트의 계보가 가장 중요하면 **Rove4k**가 적합하다. 이름의 길이·철자·의미는 이 문서의 자체 비교이며, 상표 조사나 전 세계 이름 사용 여부의 확인 결과가 아니다. npm 이름과 GitHub의 특정 소유자 아래 저장소 이름은 별도로 확인해야 한다. 웹 검색 결과가 없다는 사실만으로 확보 가능하다고 판정하지 않는다.

## 짧은 GitHub 설명

아래 문장은 복사해서 사용할 수 있는 제안이다. 아직 이번 작업에서 새 체스 엔진을 구현한 것은 아니므로, 엔진 저장소를 먼저 개설한다면 계획형 설명을 권한다.

**Rook4k — 구현 전 저장소**

```text
A UCI chess engine project targeting TCEC 4K.
```

**Rook4k — 동작하는 엔진 구현 후**

```text
A compact UCI chess engine for TCEC 4K.
```

**Rove4k — 계보를 드러내는 대안**

```text
A Rove-family UCI chess engine project targeting TCEC 4K.
```

**NVCompact — 저장소와 npm 패키지 공통 설명**

```text
N-versions compaction with verified builds, packing, and reproducible results.
```

**NVCompact — 더 짧은 설명**

```text
Compare verified build variants and pack smaller programs.
```

검증과 재현의 범위는 실제 실행 기록과 계약에 따라 달라진다. 짧은 소개 문구가 모든 프로그램의 의미 동등성이나 전역 최소 크기를 증명한다는 뜻으로 사용되면 안 된다.

## NVCompact의 뜻

이번에 이름의 설명을 다음처럼 공식화한다.

| 구성 | 뜻 | 도구에서 연결되는 기능 |
|---|---|---|
| **NV** | **N-Versions** | 여러 소스 표기·구현·컴파일·링크·압축 후보를 생성하고 비교한다. |
| **Compact** | **Compaction** | 적용 계약을 만족하는 후보 중 실제 배포 파일 전체가 작은 결과를 선택한다. |

따라서 `NVCompact`는 “여러 버전을 비교해 작게 만드는 도구”라는 이름이다. `NV`의 풀이는 이전 소스에 이미 기록된 약어를 인용한 것이 아니라, 지금 명확히 정의한 설명이다. NVIDIA나 GPU 전용 기술을 뜻하지 않으며 해당 업체와의 제휴를 나타내지 않는다.

여기서 N-Versions는 후보 포트폴리오를 가리킨다. 같은 소스의 다른 표기·컴파일 옵션을 생성한 것만으로 독립적으로 작성된 N개 구현을 얻은 것은 아니다. 여러 후보가 같은 결과를 냈다는 이유만으로 의미 보존을 자동 증명하지 않으며, 각 후보의 의미 계약·실행 검사·재현 근거를 적용한다.

명칭은 현재 기능을 설명하면서 확장을 허용한다. 체스 외의 작은 CLI, 데모, 임베디드 코드 등에도 같은 후보 생성·비교 구조를 사용할 수 있으므로, 범용 도구 이름에는 `4k`를 넣지 않는다.

## 저장소 간 관계

| 대상 | 제안 이름 | 책임 |
|---|---|---|
| 범용 개발 도구 저장소 | `nvcompact` | 후보 생성·컴파일·링크·압축·검증·재현 기능과 개발용 실험을 관리한다. |
| 공개 준비 중인 CLI 패키지 | `nvcompact` | 다른 프로젝트에서 설치할 수 있는 CLI와 Python 구현을 묶는다. |
| 향후 체스 엔진 저장소 | `rook4k` 또는 `rove4k` | 실제 엔진·목표 설정·출전 파일을 관리하고 NVCompact를 개발 도구로 사용한다. |

현재 모노레포의 `tcec4k-lab`은 기존 공개 엔진의 실험 입력과 출처를 보존하는 workspace다. 향후 자체 엔진의 이름이나 소스 구현을 대신하지 않는다. 새 엔진의 설계와 디자인은 구현 에이전트의 판단에 남긴다.

패키지 이름을 사용할 수 없거나 소유자 범위가 필요하면 `@<owner>/nvcompact`를 대안으로 선택할 수 있다. `<owner>`는 실제로 소유한 scope로 바꾸어야 하며, 이 문서에서 계정이나 이름을 예약하지 않는다.
