# 공통 엔지니어링 계약

이 문서는 구현의 목표, 의미, 재현성, 실패 수정과 수명을 규정한다. 특정 탐색·평가·병렬화·압축 알고리즘, 언어, 도구 API나 파일 구성을 선택하지 않는다. 구체 설계는 구현 에이전트가 결정하며 외부 핸드오프는 참고 자료로 사용한다.

## 1. 유효한 결과와 전체 비용

대상 게임의 규칙, 선택한 외부 프로토콜과 실제 출전 조건을 만족하는 프로그램을 만든다. 구현·배포할 대상, 사용할 수 있는 기능과 외부 의존성을 확인한다. 확인하지 않은 조건은 가정으로 표시한다. 내부에서 어떤 상태 표현이나 수 생성 방식을 쓰는지는 고정하지 않는다.

최적화는 최종 제출물 전체와 실제 실행을 대상으로 한다. 포함되는 코드·데이터·헤더·실행부·복원 기능·필수 설정의 비용을 함께 본다. 일부 payload, 원문 글자 수, 명령어 수만으로 최종 파일 개선을 주장하지 않는다. 기능의 추가 비용은 이미 존재하는 공통 기반과 결합에 따라 판단한다.

개발 도구의 비용, 시작 작업의 비용과 반복 실행 비용을 구분한다. 실행 파일에 저장하지 않은 상태도 RAM·캐시·대역폭·초기화 비용을 사용한다. 문서·상세 검증·개발 기록을 제출 런타임에 전부 내장할 의무는 없다.

**대상의 많은 코어를 활용하는 효과는 필수 설계 판단사항이다.** 전체 worker와 제어·통신·보조 작업의 CPU·메모리·시간, 경합과 작업 분배, 시작·종료 비용을 포함한다. 병렬 작업의 CPU 사용량 합계와 착수까지의 실제 경과시간을 구분하며 겹치는 wall time을 중복 합산하지 않는다. 코어·스레드 수와 정책은 실제 대상과 근거에 따라 결정한다. 단일 스레드 개선이나 총 NPS 상승이 실전 병렬 탐색의 개선을 뜻한다고 가정하지 않는다.

크기·속도·시작·메모리·기력 사이의 선택은 명시한 목표와 실제 근거에 따라 한다. 아직 측정하지 않은 우월성이나 출전 적격성을 확정하지 않는다. 어떤 후보가 최소·최선이라는 주장도 실제 조사하고 확인한 범위로 한정한다.

## 2. 구현 자유와 의미 보존

SRP·SoC는 책임, 의미와 소유권을 식별할 수 있게 적용한다. 별도 객체·호출·직렬화·프로세스·파일을 만들 의무는 없다. 인라이닝, 코드 공통화, 선택적 중복, 생성, 배치와 저수준 표현을 목적에 맞게 선택한다. 줄 수·파일 수·추상 계층·assertion 수를 할당하지 않는다.

의미 보존을 주장하는 변경은 관찰 가능한 계약, 값·타입·부작용·수명·동시성과 적용 전제를 유지해야 한다. 모델을 단순화하거나 탐색 정책을 바꾸는 것은 허용되는 별도 변경이다. 그런 변경을 무손실 압축이나 단순한 표현 변경으로 보고하지 않는다.

값과 메시지는 생성된 문맥, 보장 수준과 완료 상태에 맞게 소비한다. 제안·추정·완료 결과·규칙상 확정을 자동으로 서로 바꾸지 않는다. 이를 위해 특정 구조체·태그 폭·단일 담당 스레드·일괄 결과 선택 방식을 강제하지 않는다.

정의되지 않은 동작이나 데이터 경합에 의존하지 않는다. 공유 접근, 게시와 회수는 선택한 언어·대상의 계약을 만족해야 한다. 입력 경계와 동적으로 필요한 확인은 유지하되, 규약 준수를 위해 보장된 불변식을 매 노드·매 계층에서 반복 검증하지 않는다.

## 3. 정본, 생성물과 재현성

정본은 사람이 검토할 수 있는 원본과 선택한 입력, 생성·변환에 필요한 도구와 설정이다. 축소 코드·압축 스트림·생성된 표·실행 파일은 해당 정본에서 만들어야 한다. 생성물만 직접 고쳐서 유지되는 결과를 만들지 않는다.

재현성의 범위를 밝힌다. 같은 recipe에서 같은 파일을 만드는 것, 같은 후보 집합을 다시 조사하는 것, 비결정적 실행에서 같은 동작 계약을 만족하는 것은 서로 다른 주장이다. 필요한 입력·버전·대상·옵션·seed와 순서 조건을 보존하되, seed 하나만으로 모든 병렬 실행의 재현을 보장한다고 말하지 않는다.

압축 후 복원한 bytes의 일치는 해당 복원 경로의 근거다. 원본에서 변환한 코드의 의미 보존, 실제 대상에서의 시작과 동시성·성능을 자동으로 입증하지 않는다. 여러 후보를 생성했다는 사실도 독립적인 여러 구현으로 검증했다는 뜻은 아니다.

시간·자원 상한으로 탐색이나 실행이 끝나면 완료한 범위와 미완료 범위를 구분한다. 후보 선택은 명시한 기준과 적격성 근거를 따른다. 정상 기준선, 적용하지 않은 변환, 실패한 후보와 채택한 결과를 숨은 대체 경로로 섞지 않는다.

## 4. 실패의 원인 수정

재현 불일치, 오류와 검증 실패가 발생하면 계약·정본·변환·도구·환경·관측 중 원인이 어디에 있는지 확인한다. **잘못된 원인 로직이나 전제를 수정하는 것이 기본이다.** 관련 실패 근거를 유지하고 변경 후 실제 확인한 범위를 보고한다.

다음 방식으로 실패를 성공처럼 만들지 않는다.

- 문제가 나타난 파일명·입력·사례만 특별 취급해 잘못된 일반 로직을 유지하기.
- 검사기 우회, 숨은 옵션·환경 분기 또는 실행 조건 완화로 관측을 바꾸기.
- 실제 출력에 맞춰 기대값을 자동 갱신하거나 미완료·실패를 통과로 표시하기.
- 생성물에만 후처리를 덧붙여 정본이나 변환의 문제를 숨기기.

적용 조건을 만족하지 않는 변환은 명시적으로 적용하지 않을 수 있다. 지원하지 않는 대상은 진단할 수 있고, 확인된 ISA·ABI·기능에 따른 특수화도 허용한다. 이는 같은 종류의 입력에 일관되게 적용되는 정확한 조건과 계약에 근거해야 한다. 유효하지 않은 변환을 모든 입력에 억지로 적용할 의무는 없다.

검사 oracle이나 기존 전제가 잘못됐다면 실제 계약의 근거에 따라 수정한다. 이러한 수정과 단순한 기대값 맞추기를 구분한다. 다른 정상 후보를 선택하거나 일시적으로 사용할 수 있는 것과 원래 실패를 해결했다는 주장은 별개다.

## 5. 소유권과 수명

정본·선택된 입력, 재생성 가능한 중간물, 실패·성능 판단 근거, 최종 제출 자료와 다른 작업자의 자료를 구분한다. 모든 자료를 일반 cache로 취급하지 않는다. 보존에 필요한 입력·설정·결과를 유지하고 사용이 끝난 자신의 재생성 자료만 회수한다.

자원이 필요한 실행에는 작업에 맞는 유한한 시간·CPU·메모리·출력 범위와 종료 방법을 둔다. 독립 작업의 병렬화는 허용하되 내부 worker까지 포함한 실제 합계와 경쟁을 고려한다. 다른 프로젝트의 예산 수치나 특정 감독 구현을 자동 상속하지 않는다.

논리 취소, 물리 실행 종료, 결과 수락과 메모리·파일 재사용은 서로 다른 사건이다. 실행자가 아직 읽는 상태를 취소 표시만으로 회수하지 않는다. 정리 전에 실제 사용 종료와 소유 범위를 확인한다. 경로·소유가 불분명한 다른 자료를 임의로 회수하지 않는다.

원래 실행, 결과 보존과 정리의 성공·실패를 구분한다. 정리 성공으로 원래 실패를 덮거나 정리 실패 때문에 원래 오류를 잃지 않는다. 이를 달성하기 위해 별도 daemon·DB·영구 실행 등록부를 의무 도입하지 않는다.

## 6. 검증 책임과 근거

에이전트가 변경의 실제 위험, 유지할 계약과 주장에 맞는 검증을 선택하고 수행한다. 도구는 재생성·대조·측정·진단을 지원할 수 있지만 결과의 적용 범위와 인수 판단은 에이전트가 책임진다. 자동 검사가 정본·기대값·조건을 바꿔 스스로 통과시키게 하지 않는다.

실제 입력·출력·상태 전이·형식·불변식을 관찰한다. 정확한 수치나 구조 자체가 계약이면 확인하되 파일 개수·private 구현·소스 문장·다른 검사의 마커를 동작의 대용으로 고정하지 않는다. 버그나 문구마다 새 영구 테스트를 자동 추가하지 않는다.

기존의 유효한 검사를 먼저 활용하고 구체적인 남은 위험을 해결할 만큼 확인한다. 별도 의무 검증 프레임워크, 검증기를 검증하는 추가 계층, 전용 schema와 테스트 개수를 요구하지 않는다. 독립 관측이 필요하면 검사 대상의 같은 잘못된 로직을 기대값으로 복제하지 않는다.

원인 분리와 일반 의미 확인에 단일 스레드 실행을 사용할 수 있다. 그 결과를 실제 many-core의 공유·경합·게시·종료 계약을 확인한 것으로 확대하지 않는다. 성능 비교에는 대상 자원과 실제 실행 경로를 사용하고 경쟁 작업의 영향을 구분한다. 별도의 단순 경로를 시험한 결과를 제출 경로의 성공으로 대신하지 않는다.

같은 영향 입력·도구·환경과 실제 성공 근거가 있으면 재사용할 수 있다. cache hit 자체는 성공 근거가 아니다. 재사용·skip·실패·취소·미실행을 실제 수행한 통과와 구분한다. 관련 없는 대형 검사를 반복하거나 모든 후보마다 같은 무거운 검사 구조를 강제하지 않는다.

최종 보고에는 수행한 것과 남은 불확실성을 적는다. 작은 smoke, 더 짧은 소스, 고정 작업량의 속도와 일부 대상에서의 성공을 최종 기력·모든 대상의 적격성으로 확대하지 않는다.
