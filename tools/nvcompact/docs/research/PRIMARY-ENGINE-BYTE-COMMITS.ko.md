# ice4 · 4ku · 4k.c: 실제 바이트 절감 커밋 조사

조사 기준일: 2026-10-21. 아래 수치는 저자의 커밋 메시지 또는 변경된 README/CHANGELOG에 기록된 값이다. 이번 조사에서는 외부 엔진·부트스트랩·컴파일러·압축기를 실행하지 않았으므로 재현 실측으로 해석하면 안 된다. 한 커밋에 여러 변경이 있으면 개별 변경의 기여 바이트를 분리하지 않는다. ice4는 99525f9c6d43에서 메시지 size를 TCEC 빌드 기준으로 바꾼다고 명시하므로 그 이전 수치와 이후 수치를 연결해서 절감량을 계산하지 않는다.

## 핵심 결론

1. 원본 글자 수와 최종 제출 파일은 서로 다른 목적함수다. 4ku의 긴 미사용 인자 반복, ice4의 반복 주소식, 고정 루프 펼침은 원본을 늘리면서 압축 결과를 줄이는 후보다. native ELF가 같아도 소스를 담는 General 제출 후보를 합쳐 버리면 안 된다.
2. 조건문·삼항식·boolean 곱셈·분기 없는 대입에는 단일 우승 표기가 없다. 4k.c의 boolean 뺄셈→if는 저자 기준 -16 B였다. ice4도 boolean 곱셈→if를 채택했다. 양방향 표기를 독립 후보로 남겨 전체 파일 비용을 비교한다.
3. 이미 실패한 후보를 기록하고 검색 정책·컴파일러·압축 문맥이 바뀌면 재비교해야 한다. 제목이 줄였다고 주장해도 4k.c의 미사용 blockers→0 커밋은 CHANGELOG상 +8 B다.
4. 바이트를 줄이는 핵심은 이름·표기뿐 아니라 표현과 경계다. 내부 데이터 필드 순서, 반복 테이블, 전달 인자, 출력 포인터, 더 큰 직접 인덱스 배열, 한 번에 초기화되는 구조체, 디코더 호출 규약이 코드 크기와 압축 문맥을 바꾼다.
5. 파이프라인은 추론/검증/비용 계층을 분리한다. source parse·typed facts·원본 의미 검증은 공유할 수 있고, 같은 native bytes의 ELF 압축도 재사용할 수 있다. 반면 source payload의 비용은 source와 launcher까지 포함한 실제 바이트 및 압축 설정으로 다시 계산해야 한다.
6. 4k.c의 초기 permutation 도구는 그룹별 local search 다음 각 그룹 n!의 곱을 실제 열거했다. 이는 선언된 유한 도메인에서의 exhaustive다. 최신 warm compression의 선별은 빠른 heuristic이며 탈락 후보가 full 모델에서 더 작지 않다는 증명이 아니다. coverage에 계획·생성·중복·검증실패·계측완료·미완료를 구분한다.
7. ice4 packed-score minifier의 괄호 버그는 저자 보고 65 Elo 손실을 냈다. 빌드 성공·짧은 소스·한 bench 일치가 의미 증명은 아니다. 파싱·스코프·타입·상수 해석의 근본 로직을 고치고 예외 이름을 덧대지 않는다.

## PR #12 엔진 작업자에게 넘길 우선 후보

- 내부 Position/Move/TT 및 SearchStack 필드 순서와 AoS/SoA: 핫 필드를 짧은 displacement 범위에 놓는 후보를 비교한다. 구조체 패딩만 최소화하는 문제보다 넓다. 해시가 구조체 메모리를 읽거나 FFI/직렬화가 있으면 표현 변경도 의미에 영향을 준다.
- movegen의 count 포인터를 advancing output pointer로 바꾸거나 이미 있는 bitboard를 전달하여 lsb→shift 왕복을 없앤다. search 의미를 바꾸지 않는 API 표현 변화부터 검증한다.
- 흰색/검은색 평가의 공통 루프, 한 번 계산한 best move/history/eval 재사용, 기존 판정으로 이미 보장된 조건 제거를 검토한다. NVCompact에 엔진 이름 예외를 넣지 않는다.
- 테이블의 불용 슬롯 제거, 저/고 스트림·부호 반전·블록 오프셋 같은 lossless 표현을 우선하고, PST 칸 수 축소·가중치 재학습·TT 키 폭 축소·시간 예산 근사는 별도 성능 설계로 취급한다.
- loader/header overlap, 초기 레지스터 가정, 방향 플래그 생략, 미정의 포인터 캐스팅 같은 초소형 ELF 기법은 일반 압축기에 자동 수용하지 않는다. 정해진 OS/아키텍처 전용 백엔드로 계약과 재현 검증을 제공해야 한다.

## 아직 일반화하지 않은 경계

명시적 양방향 후보와 정의된 유한 조합 도메인을 자동 열거하는 것은 가능하다. 모든 C/C++ 의미 동치 프로그램, 모든 소스 재배열, 모든 compiler/backend/compressor의 최적 파일을 찾았다는 주장은 불가능하다. 선언한 domain 밖·예산 때문에 미완료·검증기 지원 부족을 분리 보고한다. 실패는 진단과 함께 보존하되 실패 후보를 성공 incumbent로 선택하지 않는다.

적용 여부는 Rove4k 현 구현의 채택 유무와 무관하게 기록했다. 이 문서는 아이디어와 원출처 목록이며 특정 엔진의 소스나 가중치를 이식하도록 승인하지 않는다. 라이선스 검토와 의미·성능 검증은 실제 구현 단계의 별도 의무다.
