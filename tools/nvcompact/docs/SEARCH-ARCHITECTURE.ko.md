# NVCompact 탐색 구조 개선

이 문서는 PR #13 병합 후 확인한 구조 문제와 이번 수정의 책임 경계를 기록한다.
기준은 develop `29dfde6916017b6b78d0cc1ee9f97f5a70f392e2`다. 현재는 구현 중인
설계 기록이며, 아래 계획을 이미 실행·검증한 결과로 표시하지 않는다.

## 확인한 근본 원인

- `source_search`는 단독 비용이 낮아진 spelling만 조합 목록에 넣고, 채택한 집합에
  한 개씩 추가한다. 단독 동률·열세인 대안이 함께 작아지는 경우와 다른 부분집합을
  조사하지 않는다. 후보 보존은 이 선택 오류를 고치지 않는다.
- 조건식의 all-rule/single-rule recipe는 raw 절약량 순서의 겹치지 않는 편집을
  선택한다. 개별 편집도 제한된 prefix만 만든다. 이것은 모든 적용 조합의 열거가 아니다.
- envelope의 source 비용은 원본 codec 하나이며 그 source winner 하나만 최종 codec
  탐색에 전달한다. 다른 codec에서 유리한 source를 놓칠 수 있다.
- 같은 round의 원본 C를 후보마다 다시 Clang 설정·파싱한다. spelling과 control-flow도
  frontend 실행·자원 한도·타입 모델 확인을 별도로 구현한다.
- codec refinement는 선택한 상위 seed만 확장한다. 지원 옵션 전체와 실제 선택한
  유한 후보 집합, 생성 제한과 실행 예산을 구분해서 보고해야 한다.

## 수정의 책임 경계

1. 원본 분석 세션은 고정 입력·frontend 설정·토큰·AST·타입/binding 기준을 소유한다.
   후보 생성과 검증이 같은 원본 분석을 재사용하되 후보 AST와 독립 replay는 필요한
   새 검사를 수행한다.
2. 후보 공간은 등록된 대안과 적용 근거를 정의한다. 탐색기는 비용과 별도로 대안의
   조합·순서·예산을 관리한다. 단독 비용의 열세는 조합 가능성을 제거하지 않는다.
3. 비용 평가기는 실제 제출의 header·loader·payload와 codec 조건을 소유한다.
   같은 조건의 동일 바이트만 재사용하고 소스·native·배포 파일의 동일성을 구분한다.
4. 의미 판정과 결과 선택은 측정 및 기록과 구분한다. 작은 미검증 후보가 검증된
   incumbent를 대체하지 않는다. 실패·미완료와 마지막 검증 결과를 함께 보존한다.

구체적인 타입·파일 구성은 이 책임을 구현하는 수단이며 이후 설계의 고정 규약이 아니다.
기존 최소 결과를 보존할 탐색 순서와 추가 조합의 범위, 생성 및 실행의 미완료를 실제
결과에 남긴다. 임의의 모든 동치 프로그램이나 전역 압축 최적성을 약속하지 않는다.

## 검증과 외부 조사

단독 열세인 대안의 조합, 비용 조건에 따라 달라지는 winner, 중복 분석 재사용과 fresh
replay를 실제 동작으로 확인한다. 기존 자체 예제와 고정한 공개 입력에서는 같은 조건의
baseline/candidate를 비교한다. 원래 실패를 덮거나 기대값을 새 출력으로 자동 갱신하지 않는다.

외부 엔진의 절감 커밋은 실제 diff와 source SHA를 읽어 기록한다. upstream의 보고 크기와
이 작업의 실측을 구분하고, 의미 보존·엔진 전제·모델/탐색 변경·배포 변경을 나눈다.
Rove4k 채택 여부와 관계없이 참고 아이디어를 남긴다. 외부 source/binary를 벤더링하지 않는다.
