# NVCompact의 값 영역 분석과 n-version 숏코딩 제안

## 1. 목적과 보장 범위

`advise-c`는 사용 지점의 값 영역을 근거로 여러 식을 생성하고, 같은 영역에서 결과를 비교한다.
산출물은 검토할 제안과 반례다. 압축 후보 생성, 소스 교체, 최종 파일 채택은 수행하지 않는다.
`inspect-binary`의 반복 바이트 조사, 상수 재사용 제안, 미사용 선언 진단도 각자의 관측 범위를 유지한다.

이번 설계는 세 가지 공통 원인을 해결한다. 구간만 남겨 분기 결과의 빈틈을 잃는 문제,
개별 읽기의 관측을 전체 식의 진입 영역으로 오인하는 문제, 후보마다 같은 정수 연산을 반복하는 문제다.
변수 이름이나 체스 보드 표기에 따른 예외를 추가하지 않고, 공통 영역·정수 의미·비교 경로를 개선한다.

도달 가능한 입력 집합을 `R`, 분석이 제공한 보수적 포함 집합을 `D`라고 하자.
정적 분석의 책임은 지원 범위에서 `R ⊆ D`를 유지하는 것이다.
비교기의 책임은 모든 `x ∈ D`에서 원본과 후보가 정의되어 있고 C 결과 타입과 값이 같은지 확인하는 것이다.
두 책임이 함께 성립할 때 그 지점의 순수한 식에 대한 정적 제안이 가능하다.
함수 전체, 전체 프로그램, 배포 파일의 동작까지 이 결론이 확장되지는 않는다.

| 보고 단계 | 실제 확인한 내용 | 추가로 필요한 근거 |
| --- | --- | --- |
| 정적 포함 영역 비교 | 지원하는 흐름으로 얻은 `D` 전체에서 타입·값·정의성 일치 | 바인딩, 안정된 읽기, 주변 문맥, 전체 제출물 검증 |
| 관측 구간 비교 | 관측 최소~최대 사이의 모든 정수에서 일치 | 앞으로의 모든 실행도 그 구간에 머문다는 독립 근거 |
| 영역 밖 진단 | 제한된 경계 입력에서 반례 또는 지원하지 않는 연산 발견 | 반례가 없더라도 일반 동치는 별도로 증명 |

정적 경로와 관측 경로가 같은 식 IR과 비교기를 사용한다.

비교기의 캐시는 한 요청의 변수 타입과 정확한 입력 집합에 묶이며 요청 밖으로 이동하지 않는다.
이전 파일의 위치, 다른 타입, 다른 관측 구간에서 얻은 동치 결과를 재사용하지 않는다.

## 3. 구간·알려진 비트·유한 집합을 함께 보관한다

`Domain`은 최소·최대, 비트 폭과 부호, 항상 0인 비트, 항상 1인 비트,
그리고 보관 가능한 경우 정렬된 유한 집합을 가진다. 의미는 이 조건들의 교집합이다.
유한 집합은 실제 도달 집합과 같다고 주장하지 않는다. 모든 도달 값을 포함하는 집합이면 충분하다.

예를 들어 두 분기에서 `rank=0` 또는 `rank=7`을 대입하면 `{0,7}`을 유지한다.
`0..7`로만 바꾸면 `rank&1`, 비교식, 이후 대입의 결과를 판단할 정보가 사라진다.
조건 연산자 `?:`와 `if/else`의 분기 결과는 같은 합류 원칙을 사용한다.
지원하는 순수한 식은 입력 영역의 모든 값을 평가하여 결과 집합을 얻고 C 변환까지 적용한다.
한 값에서 평가가 실패하면 그 값을 삭제하지 않고 정밀한 전파를 포기한다.

합류는 구간의 합집합을 포함하는 경계를 만들고, 양쪽에서 공통으로 확실한 비트만 유지한다.
유한 집합의 합집합이 예산 안이면 그 집합도 유지한다.
분기 조건은 기존 영역과 교차한다. `(x&mask)==value` 같은 조건도 기존 상·하한을 대체하지 않는다.
루프, 대입, 주소 유출, 지원하지 않는 제어 흐름에서 사실의 수명과 무효화 규칙을 함께 적용한다.

정확한 유한 집합은 최대 4,096개 값까지 사용한다.
흐름 환경을 복제할 때 집합은 `Arc`로 공유하고, 필터링이 필요할 때만 소유 버퍼를 얻거나 복사한다.
보고서의 사람이 읽는 `DomainSummary.values` 목록은 256개까지 표시한다.
더 큰 집합은 `finite_cardinality`와 `values_omitted`로 생략을 표시한다.
표시 목록 생략은 정적 비교기의 원래 4,096개 집합을 축소하지 않는다.

보고서만으로 관측 소속을 확인할 때 생략된 집합의 내부 빈틈까지 복원할 수는 없다.
이때 구간·알려진 비트로 복원한 넓은 집합을 사용하며 `static_membership_scope`로 확인 범위를 밝힌다.
표시 목록에 없는 값을 곧바로 불가능한 값으로 취급하지 않는다.
알려진 비트와 보수적 범위의 기본 개념은 LLVM의 [Known Bits][knownbits]와 [ConstantRange][constantrange] 문서를 참고했다.

## 4. PR #12의 rank 조건을 일반적인 연산으로 유도한다

검토할 원본과 후보는 다음과 같다.

```c
(to>>4)==0||(to>>4)==7
!(to+16&96)
```

`0 <= to <= 127`이면 `to=16*r+f`, `0<=r<=7`, `0<=f<=15`로 쓸 수 있다.
원본은 `r`이 0 또는 7일 때 참이다.
`to+16=16*(r+1)+f`에서 `96`은 비트 5와 6을 검사한다.
`r+1`의 범위는 1~8이므로 해당 두 비트가 모두 0인 경우는 1과 8이다.
따라서 이 영역에서는 두 식의 `int` 결과가 같다. 덧셈도 이 영역에서 오버플로하지 않는다.

합성기는 `16`, `96`, `to`, `0x88`을 특별한 정답으로 등록하지 않는다.
영역의 비트 폭으로 2의 거듭제곱 이동량과 연속 비트 마스크를 생성하고,
`!((x+offset)&mask)` 등을 실제 입력 집합 전체에서 비교한다.
동일한 문법은 `0..31`에서 `(lane>>2)==0||(lane>>2)==7`에 대해 `!(lane+4&24)`도 찾는다.

| 입력 또는 전제 | 원본 | `!(to+16&96)` | 판단 |
| --- | --- | --- | --- |
| 모든 정수 `0..127` | 경계 rank에서 1 | 동일 | 이 포함 영역 전체에서 일치 |
| `0..127`과 `(to&0x88)==0`의 교집합 | 64개 유효 좌표에서 판정 | 동일 | 더 작은 포함 영역에서도 일치 |
| `to=128` | 0 | 1 | 상한을 지우면 생기는 반례 |
| `to=256` | 0 | 1 | `(to&0x88)==0`만으로는 배제되지 않음 |
| 음수의 signed `to` | 오른쪽 shift가 구현 정의 | 모델별 결과에 의존 | 정적 동치로 승인하지 않음 |
| `to=INT_MAX` | 원본 rank 비교 가능 | `to+16` signed overflow | 후보 정의성 실패 |

특히 `!(to&0x88)`만으로 `0..127`을 증명할 수 없다. 검사하지 않는 상위 비트가 남는다.
보드 전제는 구간·분기·생성 경로로 입증되어야 한다. 이 규칙은 다른 보드 표현에도 같다.

같은 예에서 비교기는 서로 다른 알고리즘 형태를 함께 남긴다.
아래 길이는 표시한 식 자체의 ASCII 바이트 수이며, 원본 표기는 22바이트다.

| 후보 | 바이트 | 형태 |
| --- | ---: | --- |
| `!(to+16&96)` | 11 | 평행 이동 후 비트 검사 |
| `to<16||to>111` | 13 | 구간의 바깥 판정 |
| `(to-16&96)==96` | 14 | 다른 이동·마스크 비교 |
| `(unsigned)to-16>95` | 18 | unsigned 구간 판정 |

단순한 소스 길이만으로 압축 후 크기나 기계어 성능의 우열을 확정하지 않는다.
원본 표기, 정규화된 렌더링, 후보 표기는 각각 보존한다.

## 5. 타입이 있는 순수 정수 IR

IR은 변수, 타입 있는 상수, 단항·이항 연산, 명시적 변환, 조건 연산자를 지원한다.
정수 타입은 LP64에서 다음 여섯 가지를 구분한다.

| IR 타입 | C 타입 | 비트 | rank 관계 |
| --- | --- | ---: | --- |
| `I32` / `U32` | `int` / `unsigned int` | 32 | int |
| `I64` / `U64` | `long` / `unsigned long` | 64 | long |
| `I64LongLong` / `U64LongLong` | `long long` / `unsigned long long` | 64 | long long |

같은 64비트라도 `long`과 `long long`의 rank를 합치지 않는다.
Clang에서 내려온 각 노드의 타입과 IR이 계산한 타입이 일치해야 한다.
비교·논리 연산 결과는 `int`, shift 결과는 승격된 왼쪽 타입, 산술은 usual arithmetic conversion을 따른다.
unsigned 연산은 해당 비트 폭으로 순환한다. signed overflow, 0 나눗셈,
범위 밖 shift, 음수 signed 오른쪽 shift, 표현 불가능한 signed 변환은 승인하지 않는다.
정수 모델은 C11 LP64 2의 보수 대상이다. 관련 의미 기준은 [WG14 N1570][c11]의 §§6.3, 6.5다.

`&&`, `||`, `?:`는 선택된 부분만 평가한다.
따라서 `0&&(1/0)`의 실행되지 않은 나눗셈은 평가 오류를 만들지 않지만 `1&&(1/0)`은 실패한다.
조건 연산자는 선택된 값에도 두 가지 결과 식에서 정해진 공통 타입을 적용한다.
원본이 포함 영역의 어느 입력에서라도 모델상 정의되지 않으면 그 요청의 제안을 보류한다.
실패 입력을 제거하여 후보를 통과시키지 않는다.

렌더러는 우선순위와 결합 방향을 보존한다. `x+(1+2)`를 임의로 재결합하지 않는다.
음수 상수는 `x- -1`처럼 토큰 경계를 보존하고, signed 최솟값은
`(-2147483647-1)`처럼 상수 타입이 커지지 않는 식으로 출력한다.
64비트 값은 JSON에서도 10진 문자열로 보존하여 부동소수점 소비자의 정밀도 손실을 피한다.

호출자는 하나의 안정된 보통 변수 바인딩만 허용한다.
주소가 유출된 변수, `volatile`, atomic, 전역·정적 상태, 호출·대입 부작용을 단일 값 읽기로 바꾸지 않는다.
읽기 횟수 감소가 관측 가능한 문맥, 매크로·소스 위치 관측, 주변 구문의 요구도 별도로 검토한다.

## 6. 유한 후보 문법과 n-version 비교

후보는 직접식·불리언식, 산술, shift와 낮은 비트 마스크, 비교,
구간과 unsigned 구간, 비트 마스크, 평행 이동 후 마스크의 계열로 생성한다.
상수 재료는 원본 상수, 영역 경계, 2의 거듭제곱, 연속 비트 구간과 규칙적인 비트 묶음이다.
참 또는 거짓인 한 입력에서 마스크 비교 상수를 제안하는 역방향 생성도 사용한다.
그 한 입력은 후보를 만드는 재료이며, 통과 판정은 전체 영역 비교가 담당한다.

최근 실패한 입력을 다음 후보의 앞부분에서 검사해 빠르게 반례를 찾는다.
앞부분을 통과한 후보도 남은 모든 입력을 확인한다.
이 방식은 반례를 사용하는 합성 연구 [CEGIS][cegis]의 사고방식과 관련되지만,
현재 구현의 검증기는 유한 집합 열거이며 SMT 기반의 일반 증명기가 아니다.
합성 최적화의 참고 연구는 [Souper][souper]다.

후보는 첫 반례에서 거절할 수 있다. 이때 원본 값, 후보 값 또는 평가 오류, 입력을 기록한다.
승인된 후보는 전체 검사 값 수, 정확한 결과 타입, 영역 출처를 기록한다.
알고리즘 계열마다 최대 두 대표를 유지하고, 전체 결과 예산에서 각 계열의 첫 대표를 우선한다.
길이가 더 긴 다른 계열도 남아 실제 전체 파일 비용을 비교할 재료가 된다.
이는 제한된 대표 보존 정책이며 모든 표현식의 최적성 또는 압축 우월성을 뜻하지 않는다.

## 7. 공통 부분식과 의미 벡터 캐시

평가기는 식을 DAG로 intern하고 `(노드, 입력 위치)`별 결과를 저장한다.
캐시 결과는 정수 값 또는 구체적인 평가 오류다. 조건부로 실행되지 않은 부분은 계산하지 않는다.
따라서 원본과 후보가 공유하는 shift, 산술, 마스크를 다시 계산하는 비용이 줄어든다.

한 노드가 **전체 입력 집합**에서 평가되면 `(C 타입·rank, 전체 결과 벡터)`를 비교한다.
해시는 색인에만 사용하며, 같은 버킷 안에서도 모든 값·오류를 직접 대조한다.
정확히 같은 노드는 완성된 대표 벡터를 공유하고 중복 캐시 값을 회수한다.
대표는 요청 종료까지 유지되므로 별칭은 안정된 한 단계 참조로 남는다.
증명된 부분식 별칭은 이후 DAG 구성과 완료된 비교의 재사용에도 쓰인다.

부분 벡터는 별칭을 만들 수 없다. 예를 들어 `x&1`이 `x=0`에서 0이었다는 사실로
상수 0과 합치면 `x=1`에서 틀린다. 값이 같은 오류 없는 벡터와 오류를 포함하는 벡터도 합치지 않는다.
서로 다른 소스 표현과 계열은 별도로 유지하여 의미 캐시가 제안의 다양성을 지우지 않게 한다.
이 구현은 유한 영역의 의미 메모와 합동 재사용이다. [egg][egg]의 전체 equality saturation을 구현한 것은 아니다.

`evaluation_steps`는 캐시 조회를 포함한 평가기 방문 수다.
`computed_values`, `cache_hits`, `semantic_signatures`, `semantic_duplicates`,
`comparison_reuses`, `reclaimed_cached_values`는 실제 계산·재사용·회수를 구분한다.
재사용된 비교는 `evidence.reused=true`로 표시하며, 새 입력에서 검증한 것으로 보고하지 않는다.

## 8. 동적 관측: 식 진입과 구간의 내부를 모두 고려한다

관측은 선택한 보통 변수 읽기에 진단 함수를 삽입한 별도 소스에서 얻는다.
하나의 읽기를 한 번 평가하고 같은 정수 타입으로 반환하지만 로그·시간·스택·소스 문맥은 달라진다.
atomic 표본 할당량과 직렬화된 로그 기록은 여러 보통 스레드의 진단을 지원한다.
signal/interrupt handler에서 사용할 수 있는 계측은 아니다.

전체 식의 가설에는 그 식에 진입하면 반드시 실행되는 읽기의 표본을 사용한다.
`x&&rhs(x)`에서 오른쪽의 관측만 사용하면 `x=0` 경로가 누락된다.
공통 lowering이 `entry_site_id`를 기록하여 이런 표본 선택 오류를 막는다.
적절한 진입 읽기나 표본이 없으면 해당 식에 대한 동적 가설을 만들지 않는다.

관측 최소가 0, 최대가 10이면 가설은 모든 정수 `0..10`이다.
표본이 `{0,10}`뿐이어도 중간 5를 비교한다. 이 규칙은 `x!=5`를 항상 참이라고 제안하는 오류를 막는다.
관측된 고정 비트는 진단 정보로 보여 주지만 이 구간을 더 좁히는 증거로 사용하지 않는다.
전체 구간 비교가 성공해도 출처는 `observed_closure`이며 정적 사실은 바뀌지 않는다.

표본이 정적 포함 영역을 벗어나면 자동 축약을 진행하지 않고 입력·문맥·분석 원인을 조사하도록 보류한다.
`0..127`에서 얻은 mask 제안은 영역 밖 입력 128로 반박될 수 있다.
짧아지는 후보 최대 8개에 대해 각각 최대 32개의 영역 밖 값을 별도로 진단한다.
최소·최대의 이웃, 타입 경계, 2의 거듭제곱 등이 대상이며 `exhaustive=false`를 표시한다.
반례가 없다는 결과를 전역 불변식으로 바꾸지 않는다.

## 9. 예산과 미완료를 읽는 방법

| 예산 | 기본값 | 의미 |
| --- | ---: | --- |
| 식 대상 | 64 | 정적·관측 비교에 남길 식 지점, 수집 단계도 그 8배로 제한 |
| 유한 영역 | 4,096 | 식의 모든 입력을 열거할 수 있는 최대 개수 |
| 흐름 전파 작업 | 8,000,000 | 평가 전에 예약하는 보수적 작업 상한 |
| 정적 비교 작업 | 16,000,000 | 정적 대상 전체의 실제 `evaluation_steps` 합계 |
| 관측 비교 작업 | 16,000,000 | 관측 대상 전체에 별도로 적용하는 같은 한도 |
| 식 하나의 비교 | 2,000,000 | 단계의 남은 예산과 이 값 중 작은 쪽 |
| 식 하나의 생성 | 10,000 | 생성 후보 수의 상한 |
| 평가 메모 | 131,072 | 식 노드·입력 쌍의 최대 보관 개수 |
| 제안 / 거절 표본 | 24 / 24 | 대표 후보와 구체적인 거절 근거의 보관 한도 |
| 영역 밖 진단 | 8 × 32 | 식별 후보 수 × 후보별 입력 수, 합성 작업과 별도 계수 |

흐름 전파는 `값 수 × 2 × (lowering 노드 수+1)²`를 먼저 예약한다.
`finite_flow_reserved_work`는 실측 실행 횟수가 아니다. 실패·단축 평가가 있어도 예약을 성공한 작업으로 바꾸지 않는다.
`--profile`을 함께 쓰면 정적 최대 1,600만과 관측 최대 1,600만이 각각 적용된다.
여기에 흐름 예약과 별도로 제한된 영역 밖 진단이 있다. 한 숫자로 전체 CPU 시간을 보장하지 않는다.

지원하지 않는 식, 너무 큰 영역, 원본 평가 실패, 생성 한도, 평가 한도를 구분해 보고한다.
생략한 거절 표본 수와 미보관 동치 후보 수도 남긴다.
`SearchReport.complete=true`는 보고한 유한 후보 문법을 끝까지 생성했다는 의미다.
전체 C 문법, 모든 알고리즘, 전체 프로그램의 완전성을 의미하지 않는다.

## 10. 사용 예

저장소 소유의 [domains.c](../examples/advice/domains.c)는 명시적 상한,
0x88 마스크만 있는 경로, 관측 전용 경로와 sparse 분기 결과를 함께 비교할 수 있는 예제다.

```sh
nvcompact advise-c final.c --clang clang --standard c11 \
  --max-nversion-targets 64 \
  --max-nversion-work 16000000 \
  --max-finite-flow-work 8000000 \
  --report /absolute/external/advice.json

nvcompact advise-c final.c --instrument /absolute/external/diagnostic \
  --max-probes 128 --max-samples 100000

nvcompact advise-c final.c --profile /absolute/external/observations.log \
  --report /absolute/external/observed-advice.json
```

`--instrument`는 새 디렉터리에 진단 소스·헤더·manifest를 만든다. 빌드하거나 실행하지 않는다.
진단 빌드·실행에서 사용할 입력과 컴파일 설정은 해당 작업에서 정하며, 표본 로그를 `--profile`로 수입한다.
소스와 분석 문맥 fingerprint가 달라진 로그는 사용하지 않는다.
명령·포장 진입점과 기존 유틸리티는 [NVCompact README](../README.md)를 참고한다.

## 11. 검증과 현재 한계

단위 검사는 generic rank 사례, 128·256 반례, signed overflow, 음수 shift,
rank 변환, 단축 평가, 조건 연산자, sparse 표본, 예산 중단, 해시 충돌을 다룬다.
공통 DAG 평가기는 여섯 타입·연산자·경계값·역순 입력 방문에서 독립 scalar 평가와 대조한다.
별도 C11+UBSan 검사에서는 생성한 실제 C 식의 값과 `_Generic` 결과 타입을 확인한다.
이 검증은 평가 모델·렌더링·메모의 근거이며 제출 엔진의 기력이나 전체 파일 적격성 검증은 아니다.

현재 n-version IR은 `char`, `short`, enum, `_Bool` 저장 타입, 부동소수점, 포인터,
여러 바인딩 사이의 관계, 외부 호출 효과를 일반적으로 모델링하지 않는다.
기존 흐름 진단의 일부 `_Bool` 지원과 n-version의 지원 범위를 혼동하지 않는다.
goto·비지역 제어 흐름·일부 확장 문법은 흐름 분석을 보류하고, 지원하지 않는 switch 등에서도 정밀도를 제한한다.
큰 영역의 SMT 증명, 관계형 도메인, 전역 함수 요약, 자동 치환·배포는 별도의 후속 설계가 필요하다.
후속 확장도 같은 타입·정의성·소유 수명 계약과 예산·반례 보고를 통과해야 한다.
