# B/C/E shipping input-profile proposal

The opening section below preserves the historical source-preparation scope.
The separately executed first-cost result is recorded at the end. Its producing
five-file snapshot and original external cost index remain immutable; this
README update is post-run qualification metadata only.

This is source preparation only. The maintained B5546/C5245/E5366 entries and
all canonical, DEV, helper, compiler, resource, launcher and codec inputs remain
unchanged. No native, whole-file or functional result is claimed here.

One declared shipping policy independently ports the maintained A/F input
principles. B/E combine first-legal fallback and named legal-move parsing into
nullable `parse(board,text,&child)`, then replay its already-made child once.
C already has that exact interface and single-make replay; its parse body is
checked and preserved, with no duplicate saving counted. All families replace
manual decimal parsing, the character line reader and two clock-key branches,
and use exact first-command-token dispatch.

These are actual byte counts of a pure source transformation, not estimates
of compressed savings. Native and complete-file costs are unmeasured. Source
length does not predict the final transport's compressed length.

The ordinary `transform.py` accepts only literal current canonical and final
shipping full byte/SHA-256 domains. It projects exact owned input fragments
using family-specific function, storage and local roles; strings/characters
remain opaque. It requires one occurrence per old shipping region, fixed new
full identities, exact inverse and every unchanged complement gap. The normal
spelling/core/SIMD guards are neither replaced nor broadened. New `main`
locals reuse the freed status/suffix names `m/p/n` only in their scopes.

B/E retain their exact worker depth/score/best/nodes reset loop, ready startup
barrier, wait, epoch publication and shutdown/join body. Their `think` does
not clear `best`, so dropping that GO reset would be incorrect. C retains its
existing pending startup/wait and nullable fallback. The budget arithmetic,
TT, model21, SIMD leaf, SEE/singular, draw/mate, move generation and actual
make remain in the protected complement or literal preserved subregions.

The shipping text policy deliberately differs from the old robust reader on
malformed/unsupported input. It requires NUL-free text and accepts at most
32,767 bytes before LF or final EOF, including CR. Overlong lines are drained
and dropped. Space/tab/CR/LF delimit tokens; VT/FF do not. Commands match the
exact first token; leading delimiters and extra uci/isready/quit arguments are
accepted. Position requires exact startpos and optional moves, all legal moves
must succeed before committing board/history, and unused history tail remains.
Unsupported FEN/malformed replay is rejected without publishing scratch child.

Numbers require an ASCII first digit, full token consumption and value at
most LLONG_MAX. Signs, whitespace, junk and unsigned overflow become zero.
GO recognizes only exact wtime/btime/winc/binc. Recognized keys consume one
value even for the opponent, own-side last values win in either order, and
unknown tokens have no value arity. No own clock gives finite1000ms; present
zero/invalid/missing time gives at least1ms. Existing increment/day caps and
clock/5 cap stay unchanged. A recognized key swallowed as a malformed value
is not replayed. Stop/newgame remain tolerated no-op shipping commands.

The paired readable uses old bodies under DEV, including B/E's old two-argument
parse and E's DEV order caller. Source-only selection verifies those exact old
function bodies; actual previous DEV source/native tuple reproduction has not
run. A possible future normal builder must keep the original canonical input
for all old shipping guards and apply this new stage last. Its DEV branch can
specialize the dual readable, separately checking actual prior DEV identities.

Source preparation initially failed its own old-DEV-body equality check because
the GO extraction ended before the existing closing-brace LF. The failed helper
is preserved externally. Owning that already-existing LF in the GO region fixes
the delimiter boundary; no C body, compiler or engine run was involved. The
corrected transform passes old-body selection, role relation, inverse/complement
and final-source literal checks for all three fixed families.

The external proposal/receipt records aliases, counterexamples, input paths and
all hashes. Generated readable/C and source receipts remain outside Git.
Actual C AST/preprocessing/compiler/codec/engine/DEV generation/game/benchmark
and normal builder executions are all zero. Any first-cost or focused runtime
stage is separate work; this folder does not claim that work has happened.
