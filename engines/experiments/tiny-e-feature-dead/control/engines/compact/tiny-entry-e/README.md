# Maintained minimal E entry

`engine.c` is the readable maintained source for the qualified TinyE composition.
It contains the shipping and diagnostic forms together. Its exact hand-authored,
untrained 21-coefficient integer model supplies both the actual search leaf and
the actual move priorities. This promotion changes the regeneration inputs and
source ownership while preserving the program, resources, compiler argv,
bootstrap template and fixed codec. The shipping spelling stage below changes
the source representation and complete-file bytes while preserving native bytes.

The selected complete file is **5,679 bytes**, **1,583 bytes above 4,096**. This
folder does not establish 4 KiB eligibility, strength or many-core performance.
Its qualified environment is Ubuntu 24.04.4 x86-64, GCC 13.3.0, binutils 2.42,
glibc 2.39, Python 3.12.3 and xz 5.4.5. Python's LZMA implementation also affects
the exact compressed bytes. Expected hashes fail closed on a different result.

## Fixed source recipe

From an ordinary checkout on Linux, including WSL Ubuntu:

```sh
python3 -I -B engines/compact/tiny-entry-e/build.py --out /absolute/new/external-build --dev
```

The output must be a new absolute directory outside any Git checkout. `--dev`
adds the original diagnostic C and ELF; it does not change the shipping profile.
Two search workers, the input thread, TT bits 18 and PLY 128 are fixed. There is
no public resource option. The compiler command is exactly:

```text
cc -std=c11 -Os -pthread -DWORKERS=2 -DTT_BITS=18 -DDEV=0 -x c - -o x
```

`engine.c` is conditionally specialized by the actual compiler, lexically
compacted, and stripped of eight known shipping no-op diagnostic calls. The
fixed shipping alpha stage follows; readable C and DEV do not enter it. There
are no parameter changes, identifier trials, compiler trials or compression
sweeps. The six pinned repository
helpers are `engines/scripts/specialize.py`, `engines/scripts/minify.py`,
`engines/scripts/rename_c.py`, `engines/scripts/fixed_shipping_alpha.py`,
`engines/compact/tiny-a/stitch.py` and `engines/compact/tiny-a/pack_stream.py`.
Only `strip_dev_counters` and `source_literal` are consumed from the last two.
The builder copies and validates their LF-normalized bytes before importing
them from its external output. CRLF checkouts normalize explicitly to LF;
lone CR is rejected. `.gitattributes` preserves LF for this folder in Git.

The bootstrap template preserves the selected Python code and compiler argv;
only its single source-literal marker is filled. The complete file is the
exact 75-byte shell prefix followed by one XZ stream, LZMA2 preset 9 extreme,
`lc=3/lp=0/pb=2`, CRC64. It compiles in a private temporary directory, waits for
the compiler, handles compiler interruption, removes the directory, and
executes the unlinked native image through its file descriptor. Its external
programs remain `sh`, `tail`, `xz`, `python3` and `cc`.

Each build independently preprocesses, generates, compiles and packages twice,
compares every expected identity, and compares both complete results. Inputs,
intermediate source, compiler diagnostics, bootstrap, ELF, launcher and
`build.json` remain in the external output. The builder reads no historical
