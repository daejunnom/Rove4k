## Startup and epoch ownership

phase-contract.c adapts the A scheduling fixture only by the literal
source-event hash. phase-check.py verifies the seven exact production
replacements, preserves the full source prefix, and runs five actual C
shipping-profile schedules: success-early, success-late, fail-0,
fail-1-early and fail-1-late. Success returns 0; the three injected
pthread-create failures return the expected production status 2.
Delayed worker entry/arrival cannot admit input before pending reaches zero.
Partial creation bypasses the successful-startup wait and joins only the
threads actually created. All created threads exit and join before TT free.
The reused startup wait makes stopped=1 before the first GO, an intentional
private-state difference; real GO clears it.

epoch-contract.c includes unchanged candidate text and runs one O2 DEV0
diagnostic with four actual GO epochs. A separate scheduling gate holds
the real worker's first clock call while returning the real clock value.
An active GO replacement and an active-search position command each reach
the actual positive-pending wait. The old result completes before the next
GO publication or position/global-history reuse. Worker fields are read
only after pending zero. All four actual results are independently legal,
and both created threads join successfully before TT free.

This diagnostic intentionally causes early claim abort: completed depth is
zero and results use fallback. It covers the observed reset/wait/publication
boundaries; it does not prove deep-iteration publication, all shipping
schedules, join-failure handling, or general race freedom. There is no
TSAN or broad fault campaign.
